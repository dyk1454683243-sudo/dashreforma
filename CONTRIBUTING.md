# Contributing

Thanks for taking the time to contribute. Issues and pull requests are welcome in Portuguese or English.

## Reporting bugs and ideas

Open an [issue](https://github.com/grupomg-tech/dashreforma/issues). For bugs, say what you did, what you expected and what happened; a screenshot and the browser console output help a lot. If the bug depends on your backend's response, paste a redacted sample of the JSON.

## Development setup

```sh
git clone https://github.com/grupomg-tech/dashreforma.git
cd dashreforma
npm install
npm run dev
```

You do not need a backend: open `http://localhost:8080/dashboards/dashboard-cliente/?demo=1` to work with the built-in fictional dataset, or set `VITE_DEMO=true` in `.env.local` (see `.env.example`).

## Before opening a pull request

```sh
npm run lint
npx tsc -p tsconfig.app.json --noEmit
npm test
npm run build
```

The same checks run in CI on every pull request.

Guidelines:

- Keep pull requests focused; one change per PR.
- Add or update tests in `src/lib/*.test.ts` when you touch the data mapping (`src/lib/report.ts`) or the demo model (`src/lib/demo.ts`).
- `src/components/ui/` is generated by shadcn/ui; avoid editing it by hand.
- Match the existing code style (TypeScript, functional components, Tailwind classes).

## Tax rules

The demo model in `src/lib/demo.ts` is intentionally simple and is not a source of truth for tax rules. If you want to improve its realism (for example differentiated regimes by NCM), please cite the legal basis in the PR description.
